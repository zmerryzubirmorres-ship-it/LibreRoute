# Подключение к уже установленному Core

## Причина

Приложение из GitHub (`io.github.libreroute`) и Dev
(`io.github.libreroute.dev`) имеют раздельные ключи устройства, настройки и
подписанные права управления. Наличие ядра на сервере не подтверждает права
новой установки приложения.

Мастер считал сервер готовым только при наличии локальных OWNER-прав и готового
управляющего профиля. Остальные состояния оставались в общей ветке подготовки
установки. Восстановление владельца тоже показывало «Установка» и
«Устанавливаем LibreRoute», хотя установленный исполняемый файл сохранялся.
Этот путь передаёт служебную сборку для восстановления реестра доступа.

Без журнала телефона нельзя утверждать, какое действие выбрал пользователь.
Read-only проверка VDS89 обнаружила управляемую установку и последнюю операцию
`5893a9a4-ff30-4e90-ab48-595088859abc` в состоянии `rolled_back`.

## Изменения

- Найденное ядро блокирует обычную первичную установку независимо от локальных
  прав и наличия управляющего профиля.
- Репозиторий дополнительно блокирует запуск первичной установки по плану
  существующего узла и проверяет наличие ядра перед отправкой.
- Восстановление прав обозначено отдельно и требует явного подтверждения.
- Для найденного сервера не спрашивается название нового профиля при добавлении
  SSH-подключения.
- Единственный найденный namespace выбирается до проверки ядра через управление.
- Обновление остаётся отдельным действием с подписанным планом.

Права нового приложения автоматически из Dev не переносятся. Для нового
устройства нужны приглашение администратора либо явное восстановление через SSH.
Восстановление всё ещё передаёт служебную сборку; устранение этой передачи в
данную доработку не входит.

## Проверка

Регрессии в `ServerSetupLifecycleTest` и `ServerInstallationStateTest`:
новое приложение без прав, найденный namespace, найденная версия без namespace,
повторные вызовы настройки, план существующей установки и появление ядра после
подготовки первичного плана. Все эти сценарии запрещают повторную отправку
установки. Сохраняются проверки новой установки, отдельного обновления и
восстановления незавершённой операции после пересоздания экрана.

Исправление включено в Android 1.2.30. Версия 1.2.29 содержит прежнюю логику.
